# Rust cores with alef-generated bindings

## Context and Problem Statement

The libraries (xberg, crawlberg, html-to-markdown, liter-llm, tree-sitter-language-pack) each publish one Rust core to
many languages: Python, Node, Ruby, PHP, Go, Java, C#, Elixir, R, WASM and others. Writing and maintaining every
binding by hand repeats the same type mapping, error and async boundary in each language and lets them drift from the
core's API.

## Considered Options

* A Rust core per library, with its language bindings generated by alef from the core's public API
* Hand-written bindings per language

## Decision Outcome

Chosen option: "A Rust core per library, with its language bindings generated by alef from the core's public API",
because one generator keeps every binding in step with the core and fixes a binding defect once for every library.

alef reads the core's Rust API and generates the binding crates, packages and cross-language e2e suites configured in
each repository's `alef.toml`. The libraries moved to alef between April 9 and April 23, 2026; this record is dated
to the last of them, xberg.

### Consequences

* Good, because a public API change reaches every language in one regeneration.
* Good, because shared binding conventions (layout, ownership, errors) live in one generator and one module.
* Bad, because every library depends on alef's release cadence, and a generator defect reaches all of them at once.

### Confirmation

Each library commits an `alef.toml`, and the toolchains baseline pins `github:xberg-io/alef`. The `modules/bindings`
module holds the shared binding rules. Adoption commits: `xberg-io/crawlberg@f13442cd1d`,
`xberg-io/html-to-markdown@ce8c1c0487`, `xberg-io/liter-llm@0c3d4a69b`,
`xberg-io/tree-sitter-language-pack@8557c15091` and `xberg-io/xberg@f5dc90e4e8`.
