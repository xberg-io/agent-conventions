## Interruption

The Xberg run stopped once after 122 of 138 sessions with "context identity changed". The interactive Claude Code
install on the same machine updated itself from 2.1.318 to 2.1.319 at 09:56 CET, and the harness refused to mix agent
binaries. A frozen read-only copy of 2.1.318 (sha256 `677a2ea7`, the recorded identity) was put first on the stage
`PATH` and the run resumed with `--resume`; every session ran on 2.1.318.

## Follow-ups

* The harness should freeze the agent and generator binaries at round start (copy them into the round directory and
  run only those copies) instead of resolving `claude` and `ai-rulez` on `PATH` for every session.
* `ai-rulez generate` uses the machine-wide `~/.cache/ai-rulez` include cache and ignores `XDG_CACHE_HOME`; a round
  should generate with a private cache.
* Xberg's judge needs work before its criteria count: the swap-domain and wrong-path mutants, and the criteria the
  second judge disagrees on.
* Sceptre and Xberg criteria with fewer than four decided items need more validation samples to be graded.
